# ImageAvatar Asset Contract

ImageAvatar is an optional image-based avatar skin for the StackChan Avatar app
and the AI Agent/Xiaozhi display. It keeps the official avatar protocol and maps
the existing semantic controls onto generated LVGL image sprites.

Enable it from menuconfig:

```text
StackChan Avatar -> Avatar Skin -> Image Avatar
```

The default selection remains the official `DefaultAvatar`.

For repeatable local builds, use the git-ignored overlay file:

```text
sdkconfig.defaults.local
```

ImageAvatar overlay:

```text
# CONFIG_STACKCHAN_AVATAR_SKIN_DEFAULT is not set
CONFIG_STACKCHAN_AVATAR_SKIN_IMAGE=y
```

Local image-only overlay while no StackChan backend authorization key is
available:

```text
CONFIG_STACKCHAN_AVATAR_WS_SERVICE=n
```

After changing the overlay, delete generated `sdkconfig` and rebuild so the
Kconfig choice is regenerated from `sdkconfig.defaults` plus the overlay.

## Current Pack

The bundled pack is generated from:

```text
workspace/stackchan-image-packs/img4635-hatch-pet-stackchan-20260630/final
```

This pack is repaired with an explicit source-level face layout. Before
updating firmware assets, the pack must pass `validate_stackchan_pack.py`,
`diagnose_stackchan_semantic_fit.py`, `diagnose_stackchan_anchor_fit.py`, and
visual inspection of `qa/contact-sheet.png`, `qa/motion-sheet.png`, and the
overlay images. Do not regenerate descriptors from a pack that has not passed
those source-level gates.

Firmware assets live under:

```text
firmware/main/stackchan/avatar/skins/image/packs/assets/
```

The generated descriptors use LVGL `RGB565A8` data generated by LVGL's own
`LVGLImage.py` converter. For LVGL 9, `RGB565A8` means an RGB565 color plane
followed by an A8 alpha plane; it is not an interleaved RGB565+alpha pixel
array. Each descriptor must include the correct `header.stride`.

- one shared 320x240 body layer;
- `neutral`, `happy`, `angry`, `sad`, `doubt`, and `sleepy` expressions;

- four 48x48 right-eye frames per expression;

## Mapping Rules

Official avatar JSON, modifiers, and app/server control stay unchanged:

- `Emotion` selects the expression set.
- `leftEye.weight` and `rightEye.weight` select eye frames.
- `mouth.weight` selects mouth frames.
- normalized position maps to a small per-part pixel offset.
- visibility, rotation, and size are passed through to the LVGL image object.

Eye frame order in this pack is open to closed, while the official eye weight
semantic is closed to open. The renderer therefore reverses eye weight mapping.
Mouth frame order is closed to open, so mouth weight mapping is direct.

## Build Integration

`main/CMakeLists.txt` keeps the image skin directory out of the default build:

```text
firmware/main/stackchan/avatar/skins/image/
```

Those sources and generated descriptors are compiled only when
`CONFIG_STACKCHAN_AVATAR_SKIN_IMAGE=y`. This preserves the official
`DefaultAvatar` path and prevents unused image assets from increasing the
default firmware size.

Avatar construction goes through `stackchan/avatar/active_avatar.*`, so the
Avatar app and AI Agent/Xiaozhi display use the same configured skin. Keep this
factory as the narrow integration point instead of duplicating
`CONFIG_STACKCHAN_AVATAR_SKIN_IMAGE` checks across app and board display code.

## Device Troubleshooting

If the Avatar screen is mostly black with only scattered colored pixels, first
check the generated LVGL descriptor layout. This symptom can happen when
`RGB565A8` data is written as interleaved 3-byte pixels instead of LVGL 9's
RGB565 plane plus A8 plane. Regenerate `my_stackchan_*` descriptors from the
canonical PNGs with:

```bash
python managed_components/lvgl__lvgl/scripts/LVGLImage.py --ofmt C --cf RGB565A8
```

The generated descriptor should contain `header.stride` values such as `640`
for a 320x240 body, `96` for a 48x48 eye frame, and `192` for a 96x48 mouth
frame.

`Connect to server Failed` is emitted by the WebSocket Avatar worker in
`main/hal/hal_ws_avatar.cpp`. It is independent from image rendering. Check the
active `CONFIG_STACKCHAN_SERVER_URL`, Wi-Fi state, backend availability, and
authorization token before treating it as an ImageAvatar bug.

For image-only local testing, disable `CONFIG_STACKCHAN_AVATAR_WS_SERVICE` so
the Avatar app does not start the WebSocket worker.

For the official StackChan backend, a reachable server can still reject the
WebSocket before upgrade with `401 Unauthorized: invalid or missing MAC`. The
device-side `Authorization` header must be a Base64-encoded RSA-OAEP-SHA256
ciphertext of:

```text
<factory-mac>|<nonce>|<unix_timestamp_seconds>
```

The ciphertext must be encrypted with the backend's `rsa.server.public` key.
The weak default `secret_logic::generate_auth_token()` returns a placeholder and
is not enough for the public backend. Keep the WebSocket worker unchanged and
provide a small `secret_logic` override for the target backend/server key.
